# Upstream Solana Research Integration

This is a source-informed integration map for the GitHub repositories and supporting research cited by the supplied share. The mappings below are design adaptations; no upstream implementation was copied. Relevant source and test paths were inspected at the pinned revisions listed below. This is a targeted audit, not a line-by-line review of every file or a claim that the upstream projects were run together. Seven implementation-focused repositories were locally source-audited; the Jupiter documentation repository was separately read at its pinned commit.

## Connected data and evidence path

```text
RPC / Geyser / WebSocket observations
  -> feed adapters and YellowstoneTruthBridge
  -> MultiSourceCrossValidator (freshness, disagreement, source independence)
  -> canonical SylphEvent / FusionEnvelope and append-only FusionJournal
  -> protocol parsing and market/route research
  -> resolved, paired transport landing observations
  -> SolanaTransportTournament (research candidate or abstain)
  -> MainnetRealityTournament / evidence and review
```

The ingestion and evidence components exist in the target repository. The transport scorecard accepts resolved observations through `recordResolvedAttempt`, but no live collector feeds it automatically. A positive score is a `RESEARCH_CANDIDATE`; it has no promotion authority and cannot authorize a transaction. The landing benchmark can compare explicitly recorded, complete three-lane trials, but no live collector supplies them. The stream multiplexer is a metrics model and reports `hasLiveTransportConnection: false`; it does not subscribe to Yellowstone, Richat, shred, or WebSocket feeds. Replay capture, durable adapters, and a complete Pump.fun mainnet cohort remain unproven. No paid benchmark or on-chain transaction was run for this update.

## Local changes connected to the research

- `YellowstoneTruthBridge` accepts optional blockhash, rejects malformed values, and uses blockhash in payload/event identity so same-slot fork observations are not collapsed. `IngestionGapReconciler` tracks contiguous coverage separately from filtered receipts; recovery certificates are journaled before gaps close, with bounded backfill and regression cases in `test/platform/gap-bounds.test.mjs` and `test/platform/recovery-certificate-pipeline.test.mjs`.
- `SolanaTransportTournament` pairs same-event, same-notional attempts, scores realized edge after observed base fee, priority fee, and tip, and abstains below its evidence threshold. It cannot promote or execute a lane.
- `SolanaArbitrageGraph` no longer books an invented 15 bps atomicity premium. Graph topology does not prove a route fits one transaction or that bundle semantics survive forks. It reports atomic execution as unverified and rejects unsafe numeric input ranges.
- `StreamMultiplexer` has no pre-seeded providers, rejects invalid metrics, excludes stale/high-latency reports, and cannot claim a live transport connection. Its provider health and quorum remain caller-supplied measurements; no authenticated transport adapter currently supplies them.
- `DEXStreamParser` identifies only exact, listed program IDs as protocol candidates. It labels every event `NOT_DECODED` and leaves mint, user, amounts, price, missing transaction success state, and missing signatures unknown. It does not infer trades from generic log text or fill synthetic default amounts/signatures.
- `LandingBenchmarkEngine` uses same-digest, same-notional, same-target-slot trials across all three lanes; incomplete trials are excluded. Its default minimum is 30 complete trials per benchmark. It reports only observed latency, slot distance, and tips, exposes a lane as a review lead only after that paired sample, and never recommends a tip. The master gate is opt-in and fails closed on missing paired evidence; this path still needs independent Astra Risk/Verification review before any authority change.
- The paper terminal's position evidence panel presents five operator checks adapted from these sources: provenance/freshness, fork identity, replay coverage, all recorded execution outcomes, and settled costs. Missing source fields remain unknown. It does not claim the production engine's Bayesian posterior is connected to the separate paper terminal feed.

The graph is only used by tests in the current source tree. Its `robustArbProfitLamports` name is legacy: the value uses floating-point rates, summed basis-point costs, and caller-supplied execution probabilities. Treat it as a research heuristic, not expected value, a quote, or a trading signal. Replacing those economic semantics requires Astra Protocol/Quant review and an independent verifier under `AGENTS.md` before any runtime connection.

The current working tree also contains ongoing liquidity-depth changes in `src/intelligence/microstructure/depth-engine.ts` and `src/intelligence/master-orchestrator.ts`. The added profile path can fall back to 30 SOL reserves and `1_000_000_000_000n` virtual token reserves, and its route thresholds are heuristics. Such a profile is synthetic when no pool evidence is supplied; it must not be presented as observed market depth or used to size an order. The opt-in gate is disabled by default, and the new economics need calibrated fixtures and review before that changes.

## Pump.fun historical evidence from the share and current project state

The share's follow-up includes a Pump.fun historical RPC capture and later says a complete token-level cohort remains uncollected and undecoded. The current repository has bounded research tooling in `scripts/pumpfun-rpc-ingest.mjs`, independent file-integrity checking in `scripts/verify-pumpfun-evidence.mjs`, operator guidance in `docs/PUMPFUN_RPC_INGEST.md`, and mocked local cases in `test/pumpfun-rpc-ingest.test.mjs`. The collector requests finalized signature pages for configured program IDs and transaction responses with `maxSupportedTransactionVersion: 0`; it saves raw JSONL, SHA-256 checksums, per-program checkpoints, unresolved rows, and a manifest. A later run now retries unresolved signatures with a bounded per-run budget before continuing the cursor, and the regression case confirms a late-available transaction is captured once and removed from unresolved state. The verifier recomputes stored hashes and count/checkpoint consistency.

This code does **not** decode Pump.fun instruction/event versions, discover and verify all relevant program IDs, recover a global token census, reconcile archival-provider block gaps, support transaction versions above 0, calculate token lifecycle/price outcomes, or estimate executable P&L. A matching SHA-256 digest only checks local file consistency; it does not authenticate the RPC provider or prove completeness. No archival RPC collection or mainnet benchmark was run in this research integration. The only cohort-quality status the current capture can establish is partial, unverified research evidence with authority blocked.

The cited [Bitquery launchpad investigation](https://bitquery.io/investigations/solana-launchpad-year) follows trades from 2025-11-01 through 2026-10-07, reports 11.5 million new traded Solana tokens and a 78% Pump.fun share, and notes that about 79% of Pump.fun tokens had no trade after launch day. Its stated archive gaps include missing blocks (about 1.6% overall, concentrated on a few dates) and missing Pump.fun v2 trades from 2026-05-07 through 2026-05-26. These are the investigation's aggregate findings, not a verified census for 2025-10-01 through 2026-10-12 and not outcomes from Sylph's collector.

The [SmugCalls weekly tracker](https://smugcalls.com/pumpfun-graduation-tracker.html?s=faq) reports creation cohorts, trades, and graduation-within-24-hours, and explicitly flags capture gaps and provisional weeks. Its 24-hour, all-created-launch denominator is different from a lifetime graduation rate among traded tokens; keep the measures separate. The share also links two Dune queries: [launches and graduations](https://dune.com/queries/6773311) and [graduated tokens and peak market caps](https://dune.com/queries/7567974). Their results have not been imported or independently verified here.

This checkout now has a bounded normalized-record cohort analyzer in `scripts/analyze-pumpfun-cohorts.mjs`, with metric definitions and input limits in `docs/PUMPFUN_COHORT_ANALYSIS.md`. The existing `src/platform/cohort/cohort-engine.ts` allocates shared capital/fills; it is not a token-lifecycle analyzer. The new analyzer accepts already-decoded, source-attributed launch/trade/graduation/settled-execution records but is not connected to the raw RPC capture: the version-pinned event decoder, archive-completeness audit, real normalized cohort data, and out-of-sample analysis remain open work. It emits research-only metrics and never maps peak capitalization to executable profit or trading authority.

## Remaining research directions from the share

- **Market truth:** record provider identity, slot and block identity, observation time, replay generation, and gap status. Compare independent providers using tail latency and disagreement; do not promote an observed or deshred event to executed/finalized truth.
- **Route quality:** evaluate every hop against a coherent, fresh quote state and the actual sequential token amounts. Include fees, impact, slippage bounds, quote expiry, account locks, compute limits, and transaction size. The current graph is only a screening heuristic and does not yet perform this quote-level evaluation.
- **Execution outcome:** preserve every attempt, including no-land, failed, expired, and replaced attempts. Associate outcomes to the originating opportunity so successful-only samples cannot hide execution failures or create survivorship bias.
- **Jito path:** benchmark single transactions and bundles separately. Account for auction contention, requested compute, tips, and the possibility that uncle/fork rebroadcast loses bundle atomicity. A successful submission acknowledgement is not a landing or profit measurement.
- **Pump.fun cohorts:** do not infer a launch strategy from decoded trades alone. A useful cohort needs reproducible raw observations, launch/curve state, timestamps and slots, entry/exit outcomes, fees/tips, and failed/no-land attempts. The share does not supply a complete validated cohort, and this update did not collect live mainnet data.

## Transport scorecard contract and evidence limits

Each attempt needs a unique ID, benchmark event, program, region, congestion bucket, input notional, resolved outcome, measured costs, and gross edge. A paired sample is eligible only when all four lanes attempted the same event under the same program, region, congestion bucket, and notional. `NO_LAND` cannot carry landing latency; failed landed execution cannot claim realized gross edge. The optimizer requires at least 30 eligible paired events and a positive empirical mean net edge after observed base fee, priority fee, and tip.

Thirty matched events is a research gate, not a production confidence guarantee. The mean does not account for correlated observations, market regime changes, selection bias, or out-of-sample performance. The graph also uses supplied rates and aggregate cost assumptions: it is a candidate filter, not an executable quote. Its per-leg capacities may be denominated in different tokens, so the reported minimum capacity is not a valid root-token size bound until adapters normalize those units. Atomicity, fee math, state freshness, and route profitability need transaction-level evidence and independent review.

Upstream source patterns do not establish that the projects operate as one live system or that any strategy is profitable. Keep the no-signer/no-broadcaster boundary intact until replayable evidence supports a separately reviewed release decision.
