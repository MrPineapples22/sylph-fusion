# Upstream Solana Research Integration

This is a source-informed integration map for the GitHub repositories and supporting research cited by the supplied share. The mappings below are design adaptations; no upstream implementation was copied. Five-pattern notes now cover all 108 distinct repository roots. Review depth varies by entry: the inventory marks README-only, targeted-source, and incomplete reviews explicitly. This is not a line-by-line review of every file or a claim that the upstream projects were run together. See [UPSTREAM_REPOSITORY_AUDIT_2026-10-12.md](./UPSTREAM_REPOSITORY_AUDIT_2026-10-12.md) for the full coverage state.

The current checkout's static connectivity and source-bound verification results, including the audit's scope caveats, are recorded in [CONNECTIVITY_AUDIT_2026-10-12.md](./CONNECTIVITY_AUDIT_2026-10-12.md).

## Connected data and evidence path

```text
RPC / Geyser / WebSocket observations
  -> feed adapters and YellowstoneTruthBridge
  -> MultiSourceCrossValidator (freshness, disagreement, source independence)
  -> canonical SylphEvent / FusionEnvelope and append-only FusionJournal
  -> protocol parsing and market/route research
  -> resolved, paired transport landing observations
  -> SolanaTransportTournament (research candidate or abstain)
  -> MainnetRealityTournament / evidence and review
```

`Feed.run()` opens the captured Yellowstone gRPC subscription in the Engine when `YELLOWSTONE_URL` is configured; captured updates pass canonical ingress before they update provider health, and disconnects report a reconnecting state. The Engine dashboard now includes that same-process health report in its existing token-protected snapshot and shows configuration, transport, authentication, validated evidence, freshness, and task availability. The separate Operator Terminal displays its own provider status and does not host the Engine Feed or share its tracker, so its Yellowstone row cannot establish Engine stream state. This checkout has no live endpoint/credential verification. Separately, the transport scorecard accepts resolved observations through `recordResolvedAttempt`, but no live collector feeds it automatically. A positive score is a `RESEARCH_CANDIDATE`; it has no promotion authority and cannot authorize a transaction. The landing benchmark can compare explicitly recorded, complete three-lane trials, but no live collector supplies them. The stream multiplexer remains a metrics model and does not subscribe to Yellowstone, Richat, shred, or WebSocket feeds. Replay capture, durable adapters, and a complete Pump.fun mainnet cohort remain unproven. No paid benchmark or on-chain transaction was run for this update.

## Pump protocol compatibility gap

The local dependency is pinned to `@pump-fun/pump-sdk` 2.0.0, while the official npm package currently publishes 4.0.0. The official docs describe newer v3 bonding-curve trades, quote-mint variants, synthetic migration, and fee sweeps. PumpSwap pools also now support signed `Pool::virtual_quote_reserves` (`i128`), including negative values; quotes must use quote-vault balance plus this signed field. Older shorter account layouts treat the missing field as zero. See [official v3 trade contract](https://github.com/pump-fun/pump-public-docs/blob/main/docs/instructions/TRADE_V3.md), [negative reserve contract](https://github.com/pump-fun/pump-public-docs/blob/main/docs/NEGATIVE_VIRTUAL_QUOTE_RESERVES.md), [synthetic migration](https://github.com/pump-fun/pump-public-docs/blob/main/docs/SYNTHETIC_MIGRATION.md), and the [published SDK](https://www.npmjs.com/package/%40pump-fun/pump-sdk).

Sylph's current `src/market.ts` path decodes `BondingCurve` and rejects non-native quote mints. It does not decode PumpSwap `Pool` state in that quote path. The separate `ammExitQuote()` remains a heuristic over the bridge's SOL reserve and must not be presented as a protocol-accurate PumpSwap quote. This is a documented compatibility gap: upgrading the SDK or changing quote semantics requires protocol/quant review, updated pinned account/event fixtures, and independent verification. No SDK upgrade or live protocol request was made here.

## Remaining research directions from the share

- **Market truth:** record provider identity, slot and block identity, observation time, replay generation, and gap status. Compare independent providers using tail latency and disagreement; do not promote an observed or deshred event to executed/finalized truth.
- **Route quality:** evaluate every hop against a coherent, fresh quote state and the actual sequential token amounts. Include fees, impact, slippage bounds, quote expiry, account locks, compute limits, and transaction size. The current graph is only a screening heuristic and does not yet perform this quote-level evaluation.
- **Execution outcome:** preserve every attempt, including no-land, failed, expired, and replaced attempts. Associate outcomes to the originating opportunity so successful-only samples cannot hide execution failures or create survivorship bias.
- **Jito path:** benchmark single transactions and bundles separately. Account for auction contention, requested compute, tips, and the possibility that uncle/fork rebroadcast loses bundle atomicity. A successful submission acknowledgement is not a landing or profit measurement.
- **Pump.fun cohorts:** do not infer a launch strategy from decoded trades alone. A useful cohort needs reproducible raw observations, launch/curve state, timestamps and slots, entry/exit outcomes, fees/tips, and failed/no-land attempts. The share does not supply a complete validated cohort, and this update did not collect live mainnet data.

## Transport scorecard contract and evidence limits

Each attempt needs a unique ID, benchmark event, program, region, congestion bucket, input notional, resolved outcome, measured costs, and gross edge. A paired sample is eligible only when all four lanes attempted the same event under the same program, region, congestion bucket, and notional. `NO_LAND` cannot carry landing latency; failed landed execution cannot claim realized gross edge. The optimizer requires at least 30 eligible paired events and a positive empirical mean net edge after observed base fee, priority fee, and tip.

Thirty matched events is a research gate, not a production confidence guarantee. The mean does not account for correlated observations, market regime changes, selection bias, or out-of-sample performance. The graph also uses supplied rates and aggregate cost assumptions: it is a candidate filter, not an executable quote. Its per-leg capacities may be denominated in different tokens, so the reported minimum capacity is not a valid root-token size bound until adapters normalize those units. Atomicity, fee math, state freshness, and route profitability need transaction-level evidence and independent review.

Upstream source patterns do not establish that the projects operate as one live system or that any strategy is profitable. Keep the no-signer/no-broadcaster boundary intact until replayable evidence supports a separately reviewed release decision.

## Hosted JEV and Laya advisory connection

The hosted advisory adapter sends the same serialized Astra snapshot and typed question schema to TypeSafe Jev (`typesafe/jev-1.13`, default endpoint `https://api.typesafe.ai/v1/systemone`) and the Laya API's `clef-flash` route (`https://api.laya-ai.com/v1/systemone`), then reports each provider's status, output hash, latency, and per-signal probabilities and probability deltas. TypeSafe documents `POST /v1/systemone`, bearer authorization, and authenticated model discovery at `GET /v1/models` ([API reference](https://api.typesafe.ai/redoc)). The Laya API documents the same request format and typed `noul`/`choice`/`score` answers, and says its hosted endpoint is independently operated rather than an official ConvAI service ([API guide](https://laya-ai.com/laya-api)). `MasterIntelligenceEngine.processEvent` accepts an optional typed `astraFeatureContext` from an upstream feature adapter and retains the latest fresh/full context per mint in a bounded in-memory cache. The terminal also refreshes requested-mint market context from configured upstream sources and exposes an explicit compare action. Synthetic master-preview contexts are excluded, stale/incomplete/OOD contexts fail closed, and result data stays outside execution authority.

The local evaluation control uses fallback values for a synthetic preview. Its UI labels these as local previews, describes their evidence as synthetic, and leaves missing disagreement, escalation, and certificate values unknown. The local preview hash chain records preview state; it does not certify market evidence. The terminal's upstream feature context is accepted only when fresh evidence meets the coverage gate; market-only feeds may still leave missing features that block hosted inference. The event pipeline leaves missing Astra evidence missing instead of treating defaults as certified observations.

Configure credentials in the server process environment as `TYPESAFE_API_KEY` and `LAYA_API_KEY`; optional deadlines are `TYPESAFE_JEV_TIMEOUT_MS` and `LAYA_TIMEOUT_MS`. `TYPESAFE_API_URL` can override the documented TypeSafe endpoint and `TYPESAFE_JEV_MODEL` can override the pinned model. The status panel reports whether each credential is present but never returns its value. No credential is checked into the repository. Both hosted outputs remain advisory, uncalibrated against Sylph outcomes, and excluded from execution authority. Rotate any key pasted into chat before using it in the runtime environment.
