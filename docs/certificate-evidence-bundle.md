# Staged V2 certificate evidence bundle

`scripts/verify-certificate-evidence-bundle.mjs` adds a separate local C4 artifact-binding check. It does not change the V1 certificate generator or payload verifier. The embedded V1 certificate remains V1; enclosing it in a V2 bundle does not authenticate its issuer or award certification.

The exact bundle fields are `schemaVersion` (`SYLPH_CERTIFICATE_EVIDENCE_BUNDLE_V2`), `sourceIdentity` (`commitSha`, `treeSha`), `certificate`, and `artifacts`. Each artifact descriptor has exactly `path`, `byteLength`, `sha256`, and `canonicalRoot`. Paths must match the fixed exported `EVIDENCE_PATHS` set, including all four physical reports. Raw SHA-256 binds whitespace and exact bytes; canonical roots bind the parsed content. Descriptors are integrity commitments, not signatures.

Run `node scripts/verify-certificate-evidence-bundle.mjs PATH_TO_BUNDLE.json` from a separately trusted checkout. The strict entry point accepts only a bundle file path, parses bounded UTF-8 JSON internally (no caller objects/accessors), resolves current source identity itself, checks local files and the manifest, applies existing certificate policy, independently reruns the physical auditor and static compiler into temporary output directories, and rereads source/artifacts to detect ordinary concurrent changes. It rejects stale evidence, missing/extra/duplicate paths, symlinks, malformed descriptors, child-root mismatches, inconsistent physical/convergence data, and any C5–C10 claim. It requires convergence's `staticBaselineRoot` to match the exact scorecard; historical test reports without that field cannot pass. This change does not regenerate historical evidence or produce a current bundle.

The exported `checkEvidenceBundleContents` is a pure fixture/local consistency helper accepting caller-provided bytes and source context. Its result explicitly reports `currentSourceIndependentlyResolved: false`. Only the strict filesystem entry resolves current checkout identity. The pure helper does not reconstruct source semantics. The strict entry compares physical and static results regenerated from the identity-checked source, but neither route authenticates an issuer, verifies loaded JS/dependencies, closes M1/M4, creates a CertifiedReleaseRoot, or grants runtime/financial authority. TypeScript source-inventory binding is narrower than the executable input set (terminal JS/MJS, scripts, Rust, generated dist, environment and provider configuration).

Assumptions: trusted verifier, Git, host filesystem and OS. Before/after reads detect ordinary changes; they do not defeat a hostile administrator or all substitution races. The input bundle is unsigned. An independently provisioned issuer key/policy and level-specific durable runtime evidence remain separate prerequisites. Tests use synthetic bundles and do not constitute a production certificate.

## Independent recomputation

Strict verification reruns the physical auditor with `--output-dir` and the static compiler with `outputDir` in temporary directories. All four physical reports and the authority graph, static graph and scorecard must match regenerated content. Only each physical report’s `timestamp` and derived `manifestHash`, and scorecard `metadata.generatedAt`, may differ: timestamps must be canonical ISO UTC and not in the future; original and fresh physical hashes are independently recomputed. Every metric key/value, named test result, audited-file hash, working-tree field and all other semantic fields must match. Raw descriptors still commit to the exact original files. This is not byte-for-byte equality between separate timestamped runs.

The physical auditor runs its existing engine build and focused tests: evidence outputs are temporary, but compilation can update generated dist files in the checkout. Verification rechecks source and denies drift afterward. This is local trusted-tool recomputation, not a hermetic builder. Current stale artifacts are not regenerated in place. The focused fixture suite tests comparison rejection; no successful fresh production bundle has been demonstrated.
