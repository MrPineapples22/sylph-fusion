## JEV and Laya state flow

The current flow has two upstream paths: the engine can receive an immutable `AstraFeatureContext` during event processing, and the terminal's hosted-status request refreshes the requested mint through the configured DexScreener adapter (plus RugCheck/RPC when available), maps only observed values into an immutable context, and shows the resulting evidence coverage. Repeated fresh market observations can produce price/liquidity velocity, acceleration, and volatility; directly reported pool liquidity and market cap, provider-health error rate, RugCheck top-holder concentration, explicitly normalized RugCheck risk score, explicit bundle percentage, and optional PumpPortal trade-derived distinct buyers, buy/sell ratio, and cross-provider slot lag are included only when their sources and freshness checks pass. `score_normalised` is retained separately from the UI score and mapped from its provider 0–100 scale to a feature fraction only when within range. PumpPortal trade subscriptions remain disabled by default, are metered, and include explicitly investigated mints only after the operator enables the stream and configures an API-key URL. The explicit compare endpoint sends a context only when JEV readiness accepts its coverage and freshness. Each hosted result is pinned to that snapshot hash, bounded by timeout/response-size checks, schema validated, and labeled `ADVISORY_ONLY`. The UI exposes provider state, feature coverage, and an explicit compare action.

The local dashboard's preview endpoint intentionally uses synthetic preview values. It is not the upstream context and cannot trigger a hosted call. The live market adapter supplies only partial evidence, so the 70% feature-coverage threshold may remain unmet, especially while the metered trade stream is off or before enough market history accumulates. RugCheck's explicit `score_normalised` is carried separately, range-checked against 0–100, and mapped to a 0–1 feature only when present. The provider schema specifies the field type but not its direction; public descriptions conflict, so this remains an advisory feature following the repo's current higher-is-riskier convention and is not independent safety proof. Missing fields include first-buyer quality, wash measurements, and developer concentration; those remain unknown until real adapters provide them. Aggregate transaction counts are never used as distinct-wallet counts. A keyless Jupiter quote-only smoke test on 0.01 SOL WSOL/USDC returned a buy route through JupiterZ and a sell route through Metis, 2.203 seconds apart, with a quote-implied delta of +4.176 bps before network and landing costs. It returned no transaction and does not establish a fill or profitable strategy. A live Laya `clef-flash` smoke call using a synthetic integration fixture returned all seven typed answers and passed model/schema checks; this verifies API connectivity and response parsing, not inference quality on live tokens. No authenticated TypeSafe JEV request or real-token hosted comparison has been verified.

The user supplied a Laya bearer key in chat. It is exposed; rotate it in the Laya console before production use. It is stored only in the ignored local `.env` file and is absent from tracked source. TypeSafe JEV still needs its own `TYPESAFE_API_KEY`; the `typesafe/jev-1.13` model and default endpoint are preconfigured, with optional overrides via `TYPESAFE_API_URL` and `TYPESAFE_JEV_MODEL`. Never commit either credential; configure them only in the local secret store/environment.

## Market evidence and paper-entry boundary

`terminal/astra-feed.mjs` used to synthesize volume and liquidity when the DexScreener request failed, then mark those rows verified. That fallback has been removed. The feed now retains only direct DexScreener rows and sets `entryAllowed: false`; discovery rows are not executable quote, risk, or trading authority. An operator can request a Jupiter buy-then-sell quote pair for one observed mint; the displayed signed bps are sequential indicative quote friction at the paper buy-size setting, not a fill or profit forecast. The API and command boundaries continue to reject entry when the basket is not authorized. The bot remains paper-only.

## Risk evidence correction

RugCheck bundling/insider status is now `unknown` when the report omits a valid `graphInsidersDetected` count and contains no explicit bundle/insider risk. An explicit zero count is `clear`; a positive count or explicit risk finding is `flagged`. Counts must be nonnegative safe integers. This prevents missing report fields from satisfying discovery's clean-risk requirement. The missing, zero, and positive cases are covered by the platform contract canary.
